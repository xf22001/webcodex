收集的用户协助 ChatGPT Web 实际尝试。测量范围已完成：六项冻结用例均有可归属的
结果，包括失败。所选逐用例分类为四项答案失败（两项引用失败、两项未显示最终答案）

不表示六项任务全部通过，不支持生产成功率、模型加速或发布就绪声明。

首轮观察到的三份 JSON 答案均违反精确答案契约。早期操作员前缀要求将规范 Session ID
“with your final JSON” 一起报告，而用例只描述“containing”事实与来源的对象，
评估器则要求恰好两个键。因此，额外 Session 键既是冻结规则下的格式失败，也受到
提示歧义影响，不能全部归因于模型。后续前缀要求单独报告 Session 身份。补充 1
两份答案的事实正确，但引用不符合冻结规则；保存的答案和规则均未放宽。该批次的
通用暂停前缀还造成了非更新用例暂停，已记录的操作员跟进仍属于干预。
协议第 3 版明确规定只有更新用例暂停。

## 证据能够证明什么

首轮六项原始知识证据结论均为不可用。其中五项独立原始 fixture oracle 验证了精确
目录、源码字节、受版本控制文件、Git HEAD 和索引。首次知识源更新则记录为协调
失败，不能据此推断完整性通过。后续历史源码比较继承原始 oracle 记录并核对捕获
标记，不重建已删除 fixture 的身份，不重新运行实时 oracle，也不覆盖原始结果。

已证明需要的评估器修复包括规范行号文件匹配、合法 Session 元数据消息的独立
绑定，以及对完整捕获的 Plugin 参数解析拒绝进行严格分类。后者要求完整载荷、
审计确认的相同 Window 和主体、已知的提供者调用前验证错误、无 Session 链接、
无运行时执行阶段。此类拒绝既不算 Session 内执行，也不提供源码证据。通用覆盖
规则，以及对未知、外来、损坏或包含运行时执行证据的拒绝检查，仍保持严格。

补充尝试已实际成功获取 Plugin 知识源，包括定向中文用例。该尝试最初三次 describe
缺少 Project，在分派前被拒绝；模型随后补充必需 Project 并恢复。工具在本地成功
不代表 ChatGPT 已接收或呈现其结果。“无法加载此回复”仍是根因未知的 Host 观察；
没有为这些失败合成模型答案。

第二次知识源更新尝试成功完成了必需的初次知识读取，但周期性的 App 专用 Workbench
观察进入了同一 Server 捕获。其审计主体一致，但缺少 Window 身份和 Workflow Session
链接。协调器没有绕过覆盖：未请求检查点，源码未改变，也没有声称存在最终答案。
关闭旧组件并在下一批次更改 Apps 设置，不会追溯修复该次尝试。未来 App 来源可观测性
属于独立诊断需求，不能作为当前豁免的依据。

补充 3 的知识源更新尝试通过了独立验证：13 次规范调用，以及一次单独分类的适配器
拒绝。它观察到旧哈希拒绝，刷新索引，搜索并读取新源码，最终返回正确的当前事实与
引用。这只代表该项范围内用例通过，不代表完整六项协议通过。

同批次的 Skill 读取通过 `load_skill` 和 `read_skill_file` 获取了定义与引用资源：
六次规范调用，没有适配器拒绝，覆盖、绑定及全部必需源码检查完整。独立 oracle
通过，但用户报告 Host 回复错误，未显示最终答案。提交的空答案因此未通过答案检查。
关闭 Apps 没有消除这次已观察到的 Host 故障。

该批次的 Skill 更新最初通过普通文件 API 读取引用资源。在一次已记录的操作员反馈
之后，带定义版本约束的 `read_skill_file` 返回了哈希和范围匹配的必需引用资源。
这是有协助的恢复，不能作为无干预的资源选择结果。另有七次缺少 Window 身份的请求
仍阻止严格覆盖通过：两次 Goal 搜索返回 HTTP 200，但工具失败
（`resource_access_denied`）；三次 Workbench 请求因 Apps 关闭而返回 HTTP 400；
一次直接 Session 列表请求及一次 App 资源请求也被拒绝。缓存元数据或浏览器来源尚未
证实。没有增加豁免，没有推进检查点，定义保持不变；未显示最终答案，已提交空答案。
补充 3 的三项原始独立 fixture oracle 均通过，但 Skill 更新的 oracle 通过不能替代
缺失的覆盖或更新顺序证据。

用户报告正常刷新连接并关闭旧测试对话框后，补充 4 在相同干净构建与 Apps 设置下
完成了单独保留的 Skill 更新尝试，配置摘要不同。它最初通过普通文件 API 读取引用
资源；需要一次操作员反馈，随后版本绑定的 Skill 引用资源读取才使协调器检查点
获准。协调器修改定义后，下一次实际 `read_skill_file` 以
`skill_definition_changed` 拒绝旧版本。模型随后加载当前定义，并在新定义版本下
读取正文及引用资源。最终事实与引用正确。全部独立检查和 oracle 均通过：14 次
规范调用，无适配器拒绝。这是有协助的通过，不是无干预发现的结果。连接刷新由用户
报告；此前浏览器请求的来源以及刷新是否产生因果影响仍未证实。

已记录的本地验证包括 272 项 Python 测试和 47 项提供者测试。一次性集成 smoke
报告零个模型样本；它们验证运行时契约，不能替代实际 Web 尝试。这些检查不会更改
任何已保留的收集器结论。

## 有限的后续改进

首要且有证据支持的 T03 改进是按操作提供 Plugin 参数恢复指导：绑定后的调用应说明
Project 应在 describe 时提供。次要候选是规范的项目相对 Skill 引用路径。这些候选
来自实际输入与引用失败，不支持扩展检索调优、Memory、放宽证据门槛或新增基准。
未知的 Host 呈现故障与未来 App 来源可观测性属于独立诊断方向。所有失败调用、
干预及原始批次均继续保留在测量记录中。

公开报告不包含原始答案、捕获载荷、私有身份、凭据或操作员状态。内部模型身份、
token、缓存行为、模型轮数和比较计时未知，本文不作估计。
